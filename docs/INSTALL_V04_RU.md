# v0.4-r1: постоянный распаковщик

1. Один раз вручную заменить `.github/workflows/spyderpay-unpack.yml` автономным постоянным YAML.
2. Загрузить `spyderpay-core-update-v004-r1.zip` в корень. Не распаковывать вручную. Старые архивы не нужно редактировать: workflow выберет самый новый номер релиза и ревизии, а после успешной проверки удалит предыдущие архивы с известными именами.
3. Проверить verify и apply. При ошибке проверки ничего не будет записано в репозиторий. Защита main может потребовать reviewed PR.

Корневой pyproject.toml, включая PyJWT[crypto], входит в ZIP. GitHub workflow, .git, реальные .env и ключи запрещены. Защищённые скрипты bootstrap разрешены только с заранее известными SHA-256; существующие отличающиеся файлы не перезаписываются. Источник доверия — вручную установленный workflow и контролируемая ветка main. ZIP не является цифровой подписью автора. Verify и apply работают с одним commit SHA и проверяют один digest архива.

Это исправление доставки, не завершение банковского блока. Реальные PostgreSQL, проверки зависимостей, Bandit и внешние проверки должны пройти до заявления о готовности. Миграции только в отдельном окружении после бэкапа. Использовать `python -m spyderpay_core.postgres.ops.migrate`, не запускать тесты на рабочей БД.
