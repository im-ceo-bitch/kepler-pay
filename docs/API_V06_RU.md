# Приватный API v3 — дополнение 0.6

Все маршруты ниже доступны только service principal с единственной ролью `bank_dispatch`. Используйте подписанный протокол v3, отдельную пару учётных данных на tenant и сервис. POST требует подписанного `Idempotency-Key`, JSON-объекта и уникального nonce. Для claim заголовок не является разрешением на повторную отправку. Ответы не кешируются.

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/v3/rail/intents/{iid}/claim` | Тело `{}`. Выдать одно разрешение `submit_once`, instruction, request_ref, digest. Состояние меняется атомарно. Повтор — 409. |
| GET | `/v3/rail/intents/{iid}` | Состояние разрешения и результата, reference, provider, безопасное следующее действие. Не выдаёт разрешение отправки. |
| POST | `/v3/rail/intents/{iid}/result` | `{"outcome":"accepted"}` либо `unknown` / `not_dispatched`. Однократная неизменяемая запись, идемпотентная при том же ключе и теле. Не проводит деньги. |

Внешняя передача разрешена только после успешного ответа claim; запрос должен использовать точный reference. При таймауте claim или потере результата нельзя повторять отправку. Проверить GET, затем lookup у партнёра по каноническому reference. Если состояние неясно, открыть операционный кейс. Любое несовпадение reference/подписанного результата приводит к unknown. Запрещены автоматические повторные сетевые запросы submit. При невозможности подтвердить результат резерв сохраняется. Settlement выполняется прежним независимым маршрутом, не этим API.

В текущем релизе эти маршруты обслуживают sandbox-провайдеров. Реальные API и ключи не включены.
