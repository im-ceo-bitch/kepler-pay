# v0.11 — интеграция пяти оставшихся направлений (pre-license)

## KYC/AML и антифрод
В `SPYDERPAY_COMPLIANCE_PROVIDER_JSON` задаётся JSON `{"keys":[{"issuer":"partner-test","kid":"key-001","public_b64":"...","not_before":1700000000,"not_after":1700100000}]}`.
Вместо произвольного `evidence_ref` при включённом режиме API требуется `provider_token` — компактный EdDSA JWS, заголовок `{alg:"EdDSA",kid:"key-001",typ:"spyderpay-screening+jwt"}`. Claims: iss, aud=`spyderpay-compliance-prelicense`, iat, exp (до 900 секунд), jti, tenant, account (canonical UUID), kyc, screening, tier, evidence_digest (SHA256 lower hex). Подписывает отдельно развёрнутый доверенный gateway, предварительно аутентифицировав реального KYC-провайдера. `evidence_ref` = `provider:` + SHA256(UTF8 compact JSON массива [iss,jti]). При несовпадении любого поля API отказывает. Не передавать документы или персональные данные в JWT; внешний gateway хранит исходное доказательство в разрешённой защищённой среде. Существующие maker/checker и срок действия review сохраняются. Режим без ключей разрешает только ручную pre-license проверку. Перед переходом на provider-режим нужно прекратить ручной onboarding, обновить все реплики и заново проверить существующие accounts: старые reviews не преобразуются в подписанные. Это контракт адаптера, не интеграция с реальным AML-поставщиком.

Velocity лимиты считаются по `tenant_id/owner_id`, суммарно по счетам одного владельца. Advisory transaction lock сериализует outgoing проверки на разных счетах. Тарифы/пороги прежние, не утверждённые регулятором. Нужны реальные санкционные/PEP списки, ongoing screening, мониторинг транзакций и утверждение правил риска. PostgreSQL-тест owner velocity добавлен, но не исполнялся в текущей среде.

## POS и Wallet
`GET /v3/invoices/{id}/receipt` — только OIDC customer, фактический плательщик оплаченного/возвращённого счёта своего tenant. Возвращает минимальный чек, journal, сумму и refunded_total. Неоплаченный или чужой счёт — 404. SDK `integrations/wallet-ios` — Swift Package (HTTPS, account list, QR preview, challenge/MFA/pay, receipt recovery, card proof). Интеграционные инструкции в README пакета. `recent` в терминале продавца возвращает сохранённые ссылки на последние 100 продаж, без утверждения их статуса; `status` проверяет API и согласованность возврата.

## Резервное восстановление
`python -m spyderpay_core.postgres.ops.restore_drill /private/backup/backup_ID --service restore-lab --database sp_restore_test1234 --confirm-isolated-empty-target`
Только отдельный изолированный prelicense сервер, заранее созданная пустая БД с выделенным non-superuser owner. Оператор provision-ит `PGSERVICEFILE`, `PGPASSFILE`, `SPYDERPAY_RESTORE_AGE_IDENTITY`, `SPYDERPAY_BACKUP_TRUSTED_PUBLIC_B64`; service должен быть TLS verify-full с доверенным CA. Утилита проверяет формат 3 и текущую схему, подпись, ciphertext; создаёт приватную проверенную копию и потоково передаёт age → pg_restore, single transaction, без --clean и --create. Сверяет подписанные fingerprints и финансовые инварианты, измеряет время. Не запускается на действующей БД, требует явное подтверждение изоляции. После сбоя изолированный экземпляр уничтожает оператор; не повторять восстановление поверх непустой БД. Восстановление ролей, WAL/PITR, RPO/RTO, отказ региона и фактический запуск на оборудовании остаются внешними испытаниями.

## Spider Card
Новый клиентский APDU-контракт и Core NFC bridge, P-256 possession proof, проверка суммы/merchant/invoice до отправки команд. Только проверка владения ключом, не денежное полномочие. Нет прошивки/аттестации, нет аппаратных испытаний, нет прямой оплаты NFC. Не использовать как безопасную аппаратную карту до выбора чипа и аудита.

## Приёмка
Нет изменения схемы (9). Нет изменения GitHub workflows или trusted scripts. Все реальные деньги остаются отключёнными. Локальные Python и Swift tests — не доказательство production. Не подключены реальный IdP, банк, KYC provider, HSM, физический Secure Element; не пройдены PostgreSQL, фактический restore, Xcode/iOS и независимый аудит. Актуальный полный wallet checkout недоступен — пакет не внедрён в действующее приложение. Не включать реальные платежи.
