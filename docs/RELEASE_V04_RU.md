# Release 0.4 — Block 1 + Block 2, совместимый overlay

Исправлена несовместимость архива `-full.zip`; обновление не трогает постоянный
распаковщик. Содержит v0.3 security controls и добавляет банковский lifecycle,
схему 4, role separation, риск-review, резервирование, evidence match/consumption,
операционные случаи и отчёт сверки. Внутренний ledger остаётся единственным
бухгалтерским источником истины. Согласие, настоящие банковские доказательства и
сертификация не подменяются симуляцией. Все деньги тестовые.

## Проверки и gates

Unit/HTTP и защищённые release gate тесты запущены локально. PostgreSQL, Bandit
и зависимости в чистой среде должны быть проверены действующим GitHub CI. Внешние
интеграционные проверки с реальным IdP/банком, независимый аудит, реальный KYC/AML,
settlement batches и выписки с opening/closing balances, отказоустойчивость и
PCI DSS (если применимо) остаются открытыми. Предыдущий статус production-ready
не заявлялся и не заявляется сейчас.

Установка: [INSTALL_V04_RU.md](INSTALL_V04_RU.md). Банковский API: [API_V4_BANK_RU.md](API_V4_BANK_RU.md).

Добавлена защита старого bootstrap-скрипта: повторное исполнение `001_core.sql`
на схеме версии >2 отклоняется до сброса триггеров. Это осознанное исключение из
обычного правила неизменности применённых миграций (v2 не хранит checksum); сама
историческая схема и проводки не переписываются. Новый runner применяет 002/003
последовательно и не запускает 001 на ранее мигрированной БД.
