# v0.9 operational acceptance — private pre-license only

## Secure deployment
Build an immutable signed artifact from reviewed source; pin base-image digests and resolve a dependency lock/SBOM with provenance in the actual environment. Existing GitHub ZIP workflow is only source update CI; it does not deploy or prove runtime security. Do not expose API or bank simulator to the internet. API binds loopback, TLS reverse proxy binds local/private endpoint. Use firewall ACLs and separate authenticated ingress for ops/rail; mTLS policy and external DDoS/WAF are provider-dependent. Never put mobile users on private service credentials.

On Linux, create named `spyderpay` and `spyderpay-backup` service users and install root-owned immutable `/opt/spyderpay` code/venv. Provision `/etc/spyderpay/runtime.env` and separate `/etc/spyderpay/backup.env` via secret manager with restrictive permissions. Example units under `infrastructure/systemd` are not installed automatically. Start API with `--hardened`: `SPYDERPAY_ENV=prelicense`, credit disabled, PostgreSQL DSN explicit hostname/user/database, `sslmode=verify-full gssencmode=disable target_session_attrs=read-write sslrootcert=/absolute/trusted-ca.crt`. A hardened POS config requires remote signer. Use separate read-write primary service endpoint, not a replica. Apply migrations once with owner and runtime/backup role grants after migration. Verify restricted roles; never fix permissions by running as owner.

## Vault Transit remote signer
`SPYDERPAY_POS_KEYS_JSON` contains `active_kid`, `keys` as previously, and `remote_signer` object instead of `private_b64`: `{url, mount, key_name, key_version, ca_file, token_file, client_cert, client_key}`. Use only HTTPS origin, private CA, trusted mTLS, versioned Ed25519 transit key with no export and narrow sign-only ACL. Configured token file 0600, refresh from external credential agent. API verifies every returned signature using pinned public key; no local fallback. Real Vault/HSM not installed or tested here. Vault software key is not automatically HSM-backed. Backup signer must have a different key, token and policy. Rotate keys with overlap for verification only; remove compromised keys immediately and invalidate dependent authorizations.

## Emergency stop
Provision two independent named DB logins, one member of `spyderpay_incident_maker`, the other `spyderpay_incident_reviewer`. API login must be neither. Execute `SPYDERPAY_INCIDENT_DSN=... python -m spyderpay_core.postgres.ops.incident_gate pause INCIDENT-REFERENCE`. It waits for in-flight gated database transactions and blocks new mutations globally, including bank-dispatch claim. Already issued external send permits cannot be recalled; also stop dispatch workers and ingress. Read-only paths and selected evidence/risk/incident operations remain available. A replay of a committed idempotent request can still return prior result without a debit. To resume: reconcile first, resolve incident, maker `propose-resume INCIDENT-REFERENCE`, reviewer `confirm-resume INCIDENT-REFERENCE --request-id UUID` within 15 minutes. Both DB session identities must differ. No automatic resume. Gate audit is append-only for runtime roles, not tamper-proof against DB owner; export logs to independently controlled immutable storage.

## Encrypted backup and recovery
Apply `infrastructure/postgres/backup_role.sql` after each migration; named login only, read-only table and sequence access, TLS. Configure `PGSERVICEFILE` and `PGPASSFILE` 0600, trusted libpq service with verified certificate. `SPYDERPAY_BACKUP_PGSERVICE` names the service, `SPYDERPAY_BACKUP_AGE_RECIPIENT` is public age recipient, `SPYDERPAY_BACKUP_SIGNER_JSON` is separate remote signer config, `SPYDERPAY_BACKUP_TRUSTED_PUBLIC_B64` is independently pinned Ed25519 public key. Install approved pg_dump/age binaries in /usr/bin. Run `python -m spyderpay_core.postgres.ops.backup /var/lib/spyderpay-backup`. It exports a consistent DB snapshot, checks financial invariants, pipes custom pg_dump through age, signs ciphertext digest and source counts, verifies signature before atomic publication. No plaintext backup file. Each backup directory contains encrypted bytes, signed manifest and detached signature. Copy to independently controlled immutable storage; set retention/region with compliance. Do not keep the private decryption key on API or backup host. Logical dumps do not provide WAL/PITR; managed PostgreSQL continuous archiving and replication separately required.

Restore only into a fresh isolated `sp_restore_<unique>` database. Verify ciphertext and signature with `ops.recovery verify`, decrypt in isolated environment, use approved pg_restore workflow, never target active DB. Run `ops.recovery inspect --manifest ... --backup ... --signature ...` to compare signed source counts and invariants. Counts are not full proof of row-by-row equivalence. Validate sensitive tables and actual event/settlement recovery with independent evidence, measure RPO/RTO and document. Backup/restore rehearsal is mandatory and not claimed here.

## Availability, observability and acceptance
Run replicas with same version/key configuration behind independently configured private load balancer; managed PostgreSQL primary endpoint with failover, fencing, replication and PITR; use separate worker processes and at-least-once outbox consumer deduplication. Do not retry an unknown bank submission. DB failover requires proof that acknowledged transactions survive; select synchronous durability according to financial requirements, not arbitrary RPO. `/health/live` is process-only, local `/health/ready` checks DB schema/primary, edge denies the readiness path. Signed `/v3/ops/health` reports integrity/lag and emergency gate state. Log opaque request ID and status only, do not export credentials or payment payload. Configure SIEM and alert paging using `monitoring/alert-policy.json` as baseline. `tools/staging_probe.py --ready` is bounded local read-only smoke; real peak/soak/chaos/failover tests must run in isolated staging. Define measured throughput, p95/p99, queue depth, RTO/RPO and cost.

Go-live remains blocked pending real PostgreSQL CI, migration rehearsal, real IdP/Vault/HSM, bank specs/certification, external compliance provider, physical card/terminal, completed mobile/merchant UX, infrastructure configuration and independent security audit. No production enable switch is supplied. This document is not regulator approval.
